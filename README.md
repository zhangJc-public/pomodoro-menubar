# 番茄钟（Pomodoro）— 独立运行的 macOS 菜单栏应用

一个原生 Swift/AppKit 的番茄钟，**完全独立运行，不依赖 DSH、Node、Python 或任何第三方库**。
编译产物是一个 `Pomodoro.app`，双击即用；DSH 只用来把它写出来并编译好。

- 菜单栏显示倒计时（`🍅 24:31`），无 Dock 图标
- 到点发 **macOS 系统通知 + 屏幕右上角浮窗 + Glass 提示音**，并自动进入休息
- 支持暂停/继续、跳过、停止
- 专注/短休/长休时长可配，长休息间隔可配
- 记录每日统计（完成番茄数、专注分钟、跳过、中断、未运行期间结束）
- 统计窗口可切换时间段（今天 / 7 / 14 / 30 天 / 本月 / 全部 / 自定义日期区间），并可重置统计
- 可选开机自启

---

## 一、安装

```bash
cd pomodoro
./build.sh          # 编译并打包 build/.dev/Pomodoro.app
./install.sh        # 安装到 ~/Applications/Pomodoro.app 并启动
```

安装后菜单栏会出现 🍅。**首次启动请用 Finder 双击 `~/Applications/Pomodoro.app`**（或聚焦搜索里输入 Pomodoro／番茄钟），
不要在终端或其它宿主进程里启动——从别的进程里拉起时，进程的「负责进程」会继承成宿主，
macOS 会因此拒绝注册通知（表现为通知授权报错、系统设置里找不到本应用）。详见第八节。

首次启动时 macOS 会询问是否允许通知，选「允许」即可。

- 想装到别处：`POMODORO_INSTALL_DIR=/Applications ./install.sh`
- 卸载：`./uninstall.sh`（统计数据保留）；`./uninstall.sh --purge` 连数据一起删。

## 二、菜单说明

| 菜单项 | 说明 |
|---|---|
| 状态行 | 当前阶段与剩余时间（含结束时刻），不可点击 |
| 开始 N 分钟 | 用设置里的专注时长开始一个番茄 |
| 开始 50 分钟 | 快速开始一个 50 分钟番茄 |
| 自定义时长… | 输入任意分钟数（支持小数）后开始 |
| 暂停 / 继续 | 暂停时冻结剩余时间；继续时按剩余时间重算结束时刻 |
| 跳过当前阶段 | 提前结束当前阶段并推进（专注→休息；休息→空闲） |
| 停止 | 放弃当前阶段，回到空闲 |
| 今日：N 个番茄 · M 分钟专注 | 当日统计 |
| 统计… | 统计窗口：切换时间段、查看每日明细、重置统计 |
| 测试通知 | 立刻发一条通知 + 弹一次浮窗，并报告实际使用的通道 |
| 开机自启 | 勾选/取消登录时自动启动 |
| 设置… | 时长、长休间隔、自动开始、浮窗提醒、提示音、统计保留天数、通知方式 |
| 退出番茄钟 | 退出（退出期间不计时） |

## 三、计时规则

1. **专注 → 短休息**；每完成 `longBreakEvery`（默认 4）个专注阶段，改为**长休息**。
2. 专注结束：记入统计 → 通知 → 自动开始休息（`autoBreak`，默认开）。
3. 休息结束：通知 → 回到空闲，**不**自动开始下一个番茄（`autoNextWork` 默认关，避免无人时无限循环）。
4. **跳过**：专注被跳过时不计入完成数，只记 `skipped`，并按「该阶段已结束」的规则决定下一个休息类型；休息被跳过则直接回到空闲。
5. **停止**：专注被停止记 `interrupted`；停止休息不计数。两者都直接回到空闲。
6. **应用未运行期间到点**：只记 `endedWhileAway` 并提示一次，**不补跑、不补响**。
7. 剩余时间始终由「结束时刻 − 当前时间」算出，界面每秒刷新只负责显示，因此不会累积漂移。
8. 睡眠唤醒后会做一次对账：没到点就继续，已过点则按第 6 条处理。

## 四、统计与重置

菜单 🍅 →「统计…」打开统计窗口：

- **时间段**：下拉选择 `今天 / 最近 7 天 / 最近 14 天 / 最近 30 天 / 本月 / 全部`，或选「自定义…」
  后用两个日期选择器指定任意区间（含首尾）。
- **报表**：每天一行，列出星期、番茄数、专注分钟、跳过、中断、未运行期间结束，
  并画出当日番茄数的相对分布条；底部给出范围合计、有记录天数、有产出天数与平均值。
  时间段不超过 62 天时会列出区间内每一天（没有记录的日子显示为 0），更长的范围只列出有记录的日子。
- **复制报告**：把当前报表复制到剪贴板。
- **重置统计…**：弹出确认框，可选
  - `删除所选时间段`：只删当前时间段内的记录；
  - `清空全部记录`：删除所有历史统计；
  - `取消`。

  勾选下方的「同时重置番茄周期计数」会把 `本周期已完成 N/4` 归零（不影响历史统计）。
  重置**不会**影响设置与正在进行的计时，删除后不可恢复。

统计窗口在打开状态下会随番茄完成自动刷新。

### 统计保留上限（自动覆盖最早的记录）

「设置… › 统计保留天数」控制历史最多保留多少天，**默认 365 天**，填 `0` 表示不限：

- **记录新数据时自动淘汰**：每当新的一天产生统计，超出上限的最早记录会被删除，
  也就是"逐步覆盖最早被记录的数据"。保留 `N` 天意味着保留 `今天 ~ 今天-(N-1)`。
- **启动时也会裁剪**：如果之前设的上限更宽，启动时会按当前上限清理一次并在菜单里提示。
- **改小上限立即生效**：保存设置后马上裁剪，并提示删除了多少天。
- 时间段的计算不受影响：`全部` 指的是"当前保留范围内的全部"。
- 报表底部会显示当前保留策略与最早一条记录的日期。

关于体积：每条每日记录约占 **152 字节**，所以 365 天约 55 KB、10 年约 555 KB，
且只在番茄完成时读写一次。也就是说这个上限主要是"数据卫生"（让报表和文件保持精简），
并不会因为长期运行而明显影响系统性能。

## 五、命令行（同一个可执行文件）

```bash
APP=~/Applications/Pomodoro.app/Contents/MacOS/Pomodoro

"$APP" --selftest        # 引擎/统计/格式化/持久化自检（282 项检查）
"$APP" --ui-selftest     # 无界面构建两个窗口，做一次 UI 冒烟测试
"$APP" --status          # 当前状态 + 今日统计 + 菜单栏实例是否在运行
"$APP" --stats 7         # 统计报表；范围见下
"$APP" --reset-stats 7   # 预览将要删除的记录（不删除）
"$APP" --reset-stats 7 --yes   # 真正删除该时间段的统计
"$APP" --notify-test     # 发一条测试通知并报告通道与授权状态
"$APP" --once 25         # 前台跑一个 25 分钟专注，结束后通知并退出
"$APP" --once 0.1 --label 试跑   # 6 秒快速试跑
"$APP" --login-item status       # 开机自启：status | on | off
"$APP" --help
```

统计范围写法（`--stats` 与 `--reset-stats` 通用）：

```
today | 7 | 14 | 30 | month | all | 2026-01-01:2026-01-31
```

`--reset-stats` 不带 `--yes` 时只打印命中范围与每日明细，不做任何改动；
若菜单栏应用正在运行会拒绝执行（避免内存状态覆盖磁盘）。

`--once` 用于脚本或临时计时。若菜单栏应用正在运行，它会拒绝执行（避免两边互相覆盖状态），
加 `--force` 可强制。开始前会先对账：状态文件里若有**已过期**的残留阶段，先结算成
「应用未运行期间结束」再开始；若残留阶段**仍在进行中**，则拒绝执行（不会替它记一个番茄）。
`--once` 结束后不会留下悬空阶段。

退出码：`0` 成功；`2` 参数非法（例如 `--once 1e20`、`--once 0`、无法解析的统计范围、
未知参数）或与运行中的实例冲突。用法信息在参数非法时写到 stderr，便于脚本判断。
无参数启动菜单栏应用；`--help` 打印帮助并返回 `0`。

时长与范围都会被校验：`--once` 只接受 `0.01 ≤ 分钟 ≤ 600` 的有限数，
统计范围必须是真实存在的 `yyyy-MM-dd` 日期（`2026-02-31` 会被拒绝）。
多余参数一律视为用法错误：`--once 25 --bogus` 不会启动计时器，而是直接报错退出。

## 六、数据与文件

| 路径 | 内容 |
|---|---|
| `~/Library/Application Support/Pomodoro/state.json` | 设置 + 每日统计 + 当前阶段 |
| `~/Library/Application Support/Pomodoro/gui.pid` | 菜单栏实例的 pid（用于 `--once` 冲突检查） |
| `~/Library/Application Support/Pomodoro/state.json.bak-*` | 状态文件损坏时的自动备份 |

- 数据目录可用环境变量 `POMODORO_HOME` 覆盖（测试或便携用法）。
- 历史记录受「统计保留天数」约束（默认 365 天，`0` 为不限），超出后自动覆盖最早的记录；
  因此这个文件不会随时间无限增长（详见第四节）。
- 状态文件损坏时不会被清空：**先把原文件整体备份**，再尽力抢救可读部分。
  - 单个字段坏了只丢那个字段（例如某天少了一个数字，其它天与设置照旧保留）。
  - 某一节整体坏掉（例如 `history` 被写成了数组）时，能读的部分照样留下，
    读不出来的部分才丢弃；备份文件名带秒级时间戳，同一秒内多次损坏会追加 `-1`、`-2`，
    不会互相覆盖。
  - 抢救结果会在下次写盘时落盘，`--status` 会打印「已尽力恢复可读部分（保留 N 天记录）」。
- 状态文件是普通 JSON，可读可改；改完重新启动应用即可生效。载入时还会做一次体检：
  `NaN`／负数时长、负数周期计数、非法日期键、数值坏掉的阶段会被就地修正或丢弃，
  并写入修正后的状态（菜单里会提示「已修正状态文件中的异常数值」）。

## 七、开机自启

菜单里勾选「开机自启」即可。实现上先尝试系统登录项（`SMAppService`），
若系统拒绝（例如 ad-hoc 签名的本地应用），自动改为写入
`~/Library/LaunchAgents/local.pomodoro.plist` 并用 `launchctl bootstrap` 加载。
`./uninstall.sh` 会把两种方式都清掉。

## 八、提醒机制

每次阶段变化（开始、专注完成、休息结束、跳过）都会触发三层提醒，互相独立：

1. **屏幕浮窗**（默认开，可关）：右上角一张卡片，8 秒后自动消失，点一下可立即关闭。
   **它不需要任何系统权限**，因此是"到点一定看得见"的保底通道。
2. **系统通知横幅**：由「设置… › 通知方式」决定，四选一：
   - **自动**（默认）：系统通知已授权时用系统横幅，否则降级到 `osascript` 脚本通道。
   - **仅系统通知**：只走 `UNUserNotificationCenter`。
   - **仅 osascript 脚本**：只走 `/usr/bin/osascript`（不经 shell，参数做 AppleScript 转义，5 秒超时）。
   - **仅提示音**：不弹横幅，只播放提示音。
3. **提示音**：开启时播放一次 `Glass`。**一次阶段变化只响一次**——浮窗、横幅与声音三层
   不会各自再响一遍（横幅本身不再带声音），避免两声重叠。

也就是说，即使系统通知被拒绝，你仍会看到浮窗并听到声音。`--notify-test` 会打印实际使用的通道与授权状态。

## 九、单实例与"两个 Pomodoro.app"

菜单栏番茄钟**同时只允许运行一个实例**。第二个实例启动时会说明原因后立即退出
（终端里打印一行；双击启动则弹一个提示框），不会写入状态文件，也不会动正在运行
实例的 `gui.pid`。这是必要的：两份实例会各自持有一份内存状态并先后写同一个
`state.json`，后写的会覆盖先写的。

安装后你可能会在应用列表里看到**两个** `Pomodoro.app`：

| 路径 | 是什么 |
|---|---|
| `~/Applications/Pomodoro.app` | **正式版**。菜单栏里跑的就是它，`install.sh` 管理它，开机自启也指向它 |
| `<项目>/pomodoro/build/.dev/Pomodoro.app` | 编译产物（开发用）。`build.sh` 每次重新生成 |

两者内容完全一致（同一份 `swiftc` 产物），差别只在位置和用途。

开发构建刻意放在隐藏目录 `build/.dev/` 下：Spotlight 不索引隐藏目录，所以它不会出现在
Spotlight 搜索和应用列表里。**唯一的例外**是 LaunchServices 的注册表仍会记录这个路径
（它不看隐藏属性），但这不会让它在启动台里多出一个图标；而且即使被启动，单实例守卫
也会拦住。想要彻底不留痕，直接删掉 `build/` 即可（`./build.sh` 随时能重新生成）。

## 十、已知限制

- **应用退出期间不计时**：菜单栏应用必须在运行。想完全不占用菜单栏，请用 `--once` 配合你自己的调度。
- **启动方式影响通知注册（重要）**：请用 Finder 双击 / 聚焦搜索启动。若从终端、脚本或其它宿主进程里
  `open` 启动，该进程的「负责进程」会被继承成宿主，`usernoted` 无法校验客户端身份，
  授权请求会直接报错（系统日志：`Failed to find or validate client of identifier local.pomodoro`），
  应用也不会出现在「系统设置 › 通知」里。已实测：用 Finder 双击启动后，通知注册成功、
  列表里出现 Pomodoro、原生横幅可用。
- **通知权限被拒绝时**：横幅不出现，但浮窗与提示音仍然工作。可在「设置…」里点「打开系统通知设置」跳转。
- **ad-hoc 签名**：本机没有可用签名证书（`security find-identity` 为 0 个），因此是临时签名。
  本地编译、本地使用足够；未做开发者签名与公证，拷给别人用需要对方自行编译。
- **不做**任务清单、日历、工时报表、iCloud 同步。
- 同一时刻只允许一个菜单栏实例（`--once` 会检测并拒绝并发写状态，可用 `--force` 覆盖）。

## 十一、从源码构建

```bash
./build.sh
```

- 需要 Xcode 或 Command Line Tools（`swiftc`）。
- 不使用 Xcode 工程，也不下载任何依赖：`swiftc` 直接编译 `Sources/*.swift`。
- 编译参数：`-O -swift-version 5 -target <arch>-apple-macos13.0`，产物为 arm64（或本机架构）Mach-O。
- 构建中间文件全部写在 `./build` 下；可执行文件在 `build/.dev/Pomodoro.app/Contents/MacOS/Pomodoro`。

源码结构：

| 文件 | 职责 |
|---|---|
| `Sources/Engine.swift` | 纯状态机（不依赖 AppKit，可无界面自检） |
| `Sources/Stats.swift` | 统计时间段、报表渲染与列宽对齐 |
| `Sources/Store.swift` | `state.json` 读写、损坏备份、pid 守卫 |
| `Sources/Notifier.swift` | 通知三通道 + 提示音 + 无 shell 的进程调用 |
| `Sources/Model.swift` | 状态、通知、持久化的粘合层 |
| `Sources/MenuBarController.swift` | 菜单栏图标与菜单 |
| `Sources/ReminderPanel.swift` | 右上角浮窗提醒（不依赖系统权限） |
| `Sources/Windows.swift` | 统计窗口、设置窗口 |
| `Sources/LoginItem.swift` | 开机自启（SMAppService + LaunchAgent 兜底） |
| `Sources/CLI.swift` | 命令行模式 |
| `Sources/Format.swift` | 文本格式化与 AppleScript 转义 |
| `Sources/SelfTest.swift` | `--selftest` 的 282 项检查 |
| `Sources/AppDelegate.swift` | 应用装配 |
